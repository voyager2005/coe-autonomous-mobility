02 · Detection
2D Detector
YOLO11m
~10ms / frame on RTX 4050
Outputs 2D bounding boxes with class labels and confidence scores. Single pip install ultralytics — no flash-attn, no nvcc. INT8 quantized via TensorRT for deployment. Runs entirely on GPU.
ultralytics TensorRT INT8 C3k2 + C2PSA
VRAM usage~1.1 GB
→
3D Detector
PointPillars
~18ms / frame on RTX 4050
Fast pillar-based LiDAR detector. Produces 3D oriented bounding boxes (x,y,z,w,h,l,yaw). Can fuse with 2D results via frustum projection.
OpenPCDet ONNX export Bird-eye-view
VRAM usage~1.5 GB
↓
03 · Appearance Embedding (ReID)
Re-Identification Model
OSNet-x0.25 (lightweight ReID)
~4ms per batch of 32 crops
For every detected bounding box, crop the region from the camera frame and encode it into a 512-dim appearance vector. These embeddings are stored per track and used during the association step to re-identify objects after occlusion or missed detections. OSNet is chosen because it's tiny yet powerful — originally designed for person ReID but transfers well to vehicles.
torchreid 512-d embedding Cosine similarity Batched GPU crops
VRAM usage~0.4 GB
↓
04 · Tracking Core
Motion Prediction
Kalman Filter
Per-track state vector
Each active track maintains a Kalman state: [x, y, w, h, vx, vy, vw, vh]. On each frame, predict step moves the box forward using velocity. If detection is missed for ≤N frames, the predicted position keeps the ID alive.
Constant velocity model CPU — negligible cost
→
Association
Hungarian Algorithm
Cost matrix: IoU + ReID
Builds a cost matrix combining IoU distance (spatial) and cosine distance from ReID embeddings (appearance). Solves optimal assignment in O(n³). ByteTrack-style two-stage matching: high-conf detections first, then low-conf leftovers matched to unconfirmed tracks.
scipy.optimize ByteTrack strategy CPU — <1ms
↓
05 · Track Lifecycle Management
Birth
New Track Init
Unmatched detection → tentative track. Must be confirmed by matching in ≥2 consecutive frames before receiving a permanent ID.
Tentative → Confirmed
→
Alive
Active Track
Matched each frame. Kalman updates position. EMA smooths the ReID embedding: emb = α·new + (1-α)·old. ID persists.
EMA embeddingsα = 0.9
→
Death
Track Deletion
If unmatched for max_age frames (e.g. 30 frames = 1 sec), track is deleted. ID is retired — never recycled to avoid confusion.
max_age = 30No ID reuse

Expected throughput: With TensorRT INT8 quantization on YOLO11m + PointPillars running in parallel CUDA streams, the full pipeline (detect → embed → associate → render) should achieve ~18–25 FPS on RTX 4050 at 1280×720. Dropping LiDAR and running camera-only pushes this to ~45–55 FPS. The Kalman filter and Hungarian solver run on CPU and add <2ms total. CUDA streams allow detector and ReID model to overlap execution, hiding latency.
